# GameSir Connect на Linux — вебапка с настройкой мёртвых зон

Попытка переписать официальное Windows-приложение GameSir Connect (Electron) как
веб-приложение, которое работает с контроллером напрямую из браузера. Пока
поддерживается **GameSir Cyclone 2**: чтение и запись мёртвых зон стиков и
курков, быстрый триггер, бэкап и восстановление профилей.

Бэкенд не нужен: живое состояние пада берётся через **Gamepad API**, настройки
пишутся через **WebHID** в вендорский интерфейс контроллера. Контейнер (если он
нужен) отдаёт только статику и не требует проброса устройств.

## Запуск

```
# вариант 1: локальный статический сервер (localhost = secure context)
python3 -m http.server 8080 --directory web

# вариант 2: контейнер со статикой
docker build -t gamesir-web .
docker run --rm -p 8080:8080 gamesir-web
```

Открыть `http://localhost:8080` в Chromium и нажать «Подключить (WebHID)».
Firefox/WebHID не поддерживают.

## Живая версия

<https://givemegitpls.github.io/gamesir-webui/> — та же статика, что лежит в
`web/`, без сборки: workflow `.github/workflows/pages.yml` публикует каталог на
GitHub Pages при каждом push в `main`. Pages включаются один раз в настройках
репозитория: Settings → Pages → Source = «GitHub Actions».

HTTPS нужен не только для красоты: WebHID работает лишь в secure context, и
`https://…github.io` его даёт, в отличие от `http://<lan-ip>`.

Все варианты отдают **только страницу**: устройство из браузера открывает сам
Chromium, поэтому ни контейнер, ни хостинг не убирают необходимость в
udev-правиле (см. ниже).
Так сделано специально — проброс `/dev` в контейнер не нужен, а доступ к паду
выдаётся один раз штатным механизмом системы, тем же, которым пользуются
Steam и другие утилиты для геймпадов.

## Права на устройство

Браузер открывает `/dev/hidraw*` сам, поэтому нужен доступ к вендорскому
интерфейсу (VID `0x3537`) для того пользователя, под которым запущен браузер.
По умолчанию нода `root:root 0600`, и без прав WebHID отвечает
`Failed to open the device` (в UI на эту ошибку выводится чек-лист).

Установка (правило лежит в репозитории, ставится один раз):

```
sudo packaging/setup-udev.sh
```

Скрипт копирует `packaging/70-gamesir.rules` в `/etc/udev/rules.d/`, перезагружает
правила и применяет их к уже подключённому паду; вывод пишется в
`/tmp/gamesir-udev.txt`. Эквивалент вручную:

```
sudo cp packaging/70-gamesir.rules /etc/udev/rules.d/
sudo udevadm control --reload-rules && sudo udevadm trigger --action=change --subsystem-match=hidraw
```

Содержимое правила:

```
KERNEL=="hidraw*", ATTRS{idVendor}=="3537", MODE="0660", GROUP="input", TAG+="uaccess"
```

Что здесь важно:

- матчится только вендор GameSir, никакие другие hidraw-ноды не затрагиваются;
- **правило работает только в XInput-режиме**: вендорский интерфейс `0x3537` существует лишь там
  (индикатор HOME зелёный). В режимах DS4 (`054c:09cc`) и Switch вендорского канала нет вообще,
  и никакое правило его не вернёт — режимы переключаются на самом паде: зажать **View + Menu** на ~2 секунды
  (режимы идут по кругу, цвет индикатора HOME: зелёный = XInput, синий = DS4, красный = NS);
- живой ввод (стики, курки, кнопки) правил не требует — это Gamepad API;
- префикс `70-` не косметика: ACL по тегу `uaccess` применяется в
  `73-seat-late.rules`, поэтому правило с номером `73` или больше ставит тег
  слишком поздно и доступ молча не выдаётся;
- `MODE`/`GROUP` нужны для headless-систем без локального seat, где `uaccess`
  не срабатывает (тогда пользователя надо добавить в группу `input` либо
  заменить группу на ту, где он уже состоит, — например `uucp`).

Проверка:

```
getfacl /dev/hidraw6      # ожидается строка user:<вы>:rw-
ls -l /dev/hidraw*
```

Удаление (права отзываются при следующем переподключении/пробуждении пада):

```
sudo rm /etc/udev/rules.d/70-gamesir.rules
sudo udevadm control --reload-rules
```

Альтернатива без правил — разовый `chmod`, но его придётся повторять:
`sudo chgrp uucp /dev/hidraw6 && sudo chmod 0660 /dev/hidraw6`.

Пад агрессивно засыпает и при пробуждении может менять USB-идентичность
(`3537:0575` ↔ `3537:100b`), а нода `/dev/hidrawN` пересоздаётся. Поэтому правило
должно лежать на месте: иначе после каждого сна доступ пропадает (это ровно то,
из-за чего `Failed to open the device` появляется на ровном месте).

Если совсем не хочется трогать систему, работу с устройством можно перенести в
контейнер: демон Docker открывает ноду от root (`--device` или
`-v /dev:/dev --privileged`), а страница общается с бэкендом по HTTP — тогда
WebHID не используется вообще. Это **сознательно не сделано**: выбран текущий
подход, одно udev-правило. Причина простая — у чужих утилит ровно те же
требования, просто для DualShock 4 правило уже лежит в системе
(`steam-devices`), а вендора `3537` в стандартных наборах нет.

## Что уже работает

- живой ввод через Gamepad API: стики с сеткой-перекрестием и подсветкой осей, когда точка в центре
  (значения читаются сырыми, без мёртвой зоны прошивки — видно, если центр сбит; порог центра регулируется);
- подсказка при сбитом центре: если пад в покое (ни кнопок, ни курков), а стик стоит на месте
  больше 5 секунд и не в центре — над стиками появляется баннер с полным гайдом по калибровке из мануала
  (три шага: удержать View + Menu + Home, не трогая стики, затем нажать A, затем прогнать триггеры и стики);
  баннер держится, пока стик не вернётся в центр (калибровка требует нажимать кнопки, и это не должно его
  прятать), «Скрыть на 5 минут» убирает его для этого стика;
- распознавание модели и режима по `gamepad.id` без WebHID (XInput / DS4 / Switch) с подсказкой,
  что вендорский канал доступен только в XInput;
- чтение профилей 1–4, Shift и Light (страницы 680/680/680/680/680/635 байт);
- профили: имя (до 31 байта UTF‑8), переключение активного профиля прямо на паде (`[0x0F, 7, idx]`),
  копирование профиля в другой слот (включая слой Shift), снимок сессии всех страниц с откатом в один клик;
- общие настройки профиля: частота опроса (250 / 500 / 1000 Гц), блокировка диагоналей крестовины,
  слой Shift; раскладка ABXY переключается на самом паде (M + A), в профиле её служебные байты только показаны;
- мёртвые зоны отдельными секциями: «Стики» (LS, RS) и «Курки» (LT, RT), сетка в два столбца;
- clicky-курки LT/RT (вкл, порог срабатывания, порог отпускания) — в той же секции курков;
- ремап 16 кнопок: до трёх целей на кнопку (любая клавиша, NumPad, кнопки мыши, кнопки геймпада, функции),
  turbo (вкл + скорость) и режим toggle по нажатию;
- переключатель раскладки A/B и X/Y (Xbox / Switch) — реализован как четыре ремапа, ровно так, как это
  делает сам пад комбинацией M + A;
- макросы L4 и R4: до 30 шагов, у каждого действие и время удержания/задержки в миллисекундах,
  плюс режимы «вкл», «запуск по нажатию», «цикл» и пауза цикла;
- словарь действий (144 записи) выгружен из вендорского приложения и лежит в `web/js/actions.json`;
- подсветка (страница Light, 635 байт): активная анимация, пять анимаций (кадров/эффектов, скорость, яркость),
  восемь кадров по пять зон RGB — цвет Home и четырёх подсветок под кнопками ABXY, плюс audio-reactive,
  цвет профиля, пробуждение при подъёме и таймаут сна. Скорость в профиле хранится инвертированной
  (20 − значение), в интерфейсе показывается обычной;
- полоса индикации нажатий в живом блоке, разложенная как корпус пада: стики и курки с бамперами LB/RB
  (под прогрессбарами), а строкой ниже — крестовина и ABXY (Y сверху, X слева, B справа, A снизу),
  затем служебные кнопки (View, Menu, L3, R3, Home) и всё, что пад отдаёт сверх стандартного;
  подсвечивается то, что пад реально отдаёт хосту, поэтому после ремапа кнопка перестаёт загораться;
- переключатель раскладки (Xbox / Switch) находится в секции «Общее → Раскладка ABXY» и показывает
  текущее состояние: активна та кнопка, на которую можно переключиться;
- вертикальные индикаторы курков в живом состоянии, рядом с кругами стиков;
- запись только изменённых байтов (диффами) с чтением назад и проверкой;
- бэкап всех страниц в JSON и восстановление из файла.

Проверено на железе: запись одного байта `0x229` (центр дедзоны левого стика)
изменяет поведение именно левого стика, откат восстанавливает профиль побайтово.

## Инструменты

```
tools/c2.py                     # hidraw CLI: dump / read / verify / set
tools/restore.py                # восстановление страниц из бэкапа (--dir или --json), с --dry-run
tools/check-roundtrip.mjs       # прогон живых дампов через наши кодировщики маппингов и макросов
tools/extract-actions.py        # выгрузка словаря кодов действий из app.asar -> web/js/actions.json
tools/watch.py                  # наблюдение за кадрами конфиг-канала (переживает переподключение)
tools/capture-calibration.sh    # записать, что пад шлёт при калибровке на самом паде
tools/capture_fixtures.py       # снять сырые кадры протокола в фикстуру
tools/stick2.py                 # записать поток отчётов состояния пада
tools/test-protocol.mjs         # проверка web/js/protocol.js на фикстуре
tools/test-gamepad.mjs          # распознавание vendor/product/режима по gamepad.id
tools/test-udev.mjs             # генератор udev-команд (включая защиту от инъекции в GROUP)
tools/test-page.mjs             # структурная проверка страницы: id, импорты, обвязка
```

```
python3 tools/c2.py dump                # бэкап страниц 1-4, 5, 32 в /tmp/opencode/c2-backup
python3 tools/c2.py verify 1 BACKUP.bin # сверить страницу с файлом
python3 tools/c2.py set 1 0x229 50      # изменить один байт (с чтением назад)
python3 tools/restore.py --dir DIR --dry-run 1     # предпросмотр восстановления страницы
python3 tools/restore.py --dir DIR 1 4             # восстановить страницы 1 и 4
node --test tools/*.mjs                 # тесты протокола, режимов, udev и страницы
```

Сами udev-команды страница генерирует на месте (раздел «Права на устройство»): правило,
установка через `sudo tee`, перезагрузка правил, проверка `getfacl`, удаление и запасной
вариант с `chgrp`/`chmod` без файла правила. Группа выбирается в интерфейсе
(`input` / `uucp` / только `uaccess`); значение проверяется на допустимые символы, так что
мусор в поле не попадает в shell.

## Протокол (кратко)

- вендорский интерфейс: OUT report id `0x0F` (63 байта), ответы — IN `0x10`,
  поток состояния — IN `0x12` (≈1 кГц);
- команды: `0x01` вход в конфиг, `0x02` выход, `0x03` запись чанка,
  `0x04` чтение чанка, `0x09` версия прошивки, `0x0B` активный профиль,
  `0xF2` heartbeat; ack = команда + 1;
- чтение чанка: `[0x04, page, offHi, offLo, len]`, ответ эхом возвращает
  page/offset/len и до 58 байт данных;
- запись: `[0x03, page, offHi, offLo, len, ...payload]`, не больше 58 байт за пакет.

Подробности разбора, раскладка профиля и смещения — в
[`.opencode/NOTES.md`](.opencode/NOTES.md).

## Что не сделано

- калибровка из приложения (отложена): пад не присылает `CalibrationResponse` сам, нужен хост-запрос
  `0xFD`/`0xFE`, значения режимов ещё не расшифрованы. Сама калибровка делается на паде: удерживать
  **View (два квадрата) + Menu (☰) + Home** и не трогать стики в фазе центрирования;
- кривые стиков/курков, маппинг кнопок, макросы, подсветка (смещения известны,
  интерфейса нет);
- запись страницы Light (только чтение);
- точная шкала значения дедзоны (значение 50 перекрывает заметно меньше
  половины хода — нужен замер);
- модели, где конфиг спрятан в вендорских Windows-библиотеках
  (`sapjoyuniapis_*.dll`): Tarantula Pro, Nova, G7 Pro и прочие — для них нужна
  отдельная реимплементация протокола.
