        Живое состояние выше работает всегда: Gamepad API прав не требует. А вот
        вендорский интерфейс (запись настроек) — это отдельная hidraw-нода
        /dev/hidrawN, по умолчанию root:root 0600, поэтому
        браузеру нужно выдать доступ один раз. Пад агрессивно засыпает, при
        пробуждении нода пересоздаётся — правило должно лежать на месте, иначе доступ
        отваливается снова. Команды ниже собираются на месте под твою систему.
      

      

        Почему чужие утилиты обходятся без правил: доступ им нужен такой же, просто их
        устройство уже покрыто дистрибутивом. Для DualShock 4 правило лежит в системе
        (на Arch — пакет steam-devices, файл 60-steam-input.rules:
        ATTRS{idVendor}=="054c", ATTRS{idProduct}=="09cc"). Наш пад попадает
        под него только в DS4-режиме, а в XInput он 3537:xxxx — такого вендора
        нет ни в steam-devices, ни в 70-uaccess.rules (там про
        джойстики только SUBSYSTEM=="input", то есть event*/js*,
        но не hidraw). Вендорский интерфейс не выглядит как input-устройство, поэтому
        системе о нём знать неоткуда.
